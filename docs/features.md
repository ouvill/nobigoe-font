# 機能と使い方

[READMEへ戻る](../README.md)

のびごえ明朝とのびごえこぶり明朝に共通する入力方法とOpenType機能、のびごえエッセンシャルで利用できる伸長記号、およびのびごえこぶり明朝固有の機能を説明します。

## 連続する伸長記号

次の文字を2文字以上続けると、OpenTypeの`calt`（Contextual Alternates）で始端・中間・終端の字形へ置換します。

| 文字 | Unicode | 動作 |
|---|---:|---|
| `ー` | U+30FC | 長音記号を連結 |
| `―` | U+2015 | HORIZONTAL BARを連結 |
| `〜` | U+301C | WAVE DASH（波ダッシュ）を連結 |
| `～` | U+FF5E | U+301Cと同じWAVE DASH字形を使用 |
| `〰` | U+3030 | Manga1方式のWavy Dashを連結 |

のびごえエッセンシャルがUnicodeへ直接割り当てる文字は、この5文字だけです。表の連結機能に加えて、横組・縦組と`ss04`・`ss05`の波形切替に必要な出力字形を内部に保持します。他の文字は後続のフォールバックフォントで表示されます。


横組と縦組の両方に対応しています。`〜`と`～`の連結部分は1文字あたり3半波で、開始位相を-0.5半波にしています。始端・終端の位相補正は行わず、同じ文字だけを続けた場合は始端から終端まで波長を一定に保ちます。連続時の外側には単独字形と同じ約50 unitsの余白と線幅テーパーを適用します。

生成する連結記号の黒みは、フォント内の本文字形から自動的に決めます。`あいうえおかきくけこさしすせそたちつてとなにぬねのはひふへほまみむめもやゆよらりるれろわをん`の輪郭を`2 × ink area / outline perimeter`で測り、その中央値を横組・縦組ごとの基準線幅とします。連結する`ー`・`―`は接続方向と直交する軸だけを拡縮し、波線は既定・`ss04`・`ss05`・`〰`・周波数遷移の各波形を同じ基準線幅へ揃えます。始端・中間・終端には同じ倍率を使うため、接続面の線幅は一致します。波線内の山・谷と中央線を横切る位置の線幅差は元グリフから保持し、位相に応じて補間します。外側の線幅テーパーには、この位相別線幅へ滑らかな縮小率を掛けます。

`ss04`を有効にすると、2文字以上連続する`〜`と`～`を1文字あたり2.5半波（1.25周期）のゆるやかな波形へ切り替えます。位相の異なる4字形を順番に使用し、外側でも位相を補正しないため、始端から終端まで波長は一定です。開始位相は元グリフの輪郭に合わせて-0.25半波とし、連続時の外側には既定版と同じ余白と線幅テーパーを適用します。単独字形は`ss04`の有無にかかわらず、既定字形を使用します。

`ss05`を有効にすると、2文字以上連続する`〜`と`～`を1文字あたり2半波（1周期）の波形へ切り替えます。各文字の始端と終端が同じ位相になるため、反転字形や位相循環を使わず、同じ中間字形を反復します。専用調整値は開始位相-0.5半波、始端・終端の位相補正なし、振幅は既定版の1.2倍、線幅テーパーは外側1/6文字幅とし、既定版と同じ余白を適用します。単独字形は`ss04`・`ss05`の有無にかかわらず、既定字形を使用します。`ss04`と`ss05`は同時に指定せず、どちらか一方だけを有効にします。

既定波形（`ss04`・`ss05`ともに無効）では、`〰`と`〜`または`～`を続けると、`calt`が文字種の境界を1本の線として双方向に接続します。`〰`は1文字2周期、通常の`〜`・`～`は1文字1.5周期のまま扱い、境界直後の文字を1.75周期の遷移字形へ置換します。`〰`から`〜`・`～`へ移る場合は2周期から1.5周期へ滑らかに減速し、逆方向では1.5周期から2周期へ滑らかに加速します。遷移字形の両端では中心線の位置と接線を隣の字形へ一致させます。位相状態を`calt`内で左から右へ伝播するため、`〰〰〜〜〰〰`のような列だけでなく、`〜〰〜〰〜`のように1文字ごとに切り替わる列も途中で途切れません。`〰`を後続文字の波形を選ぶ制御文字としては扱わず、各入力文字をその文字種の波として表示します。

既定の1文字1.5周期の`〜`・`～`および1文字2周期の`〰`と、`ー`・`―`が隣接する境界も、横組・縦組の両方で`calt`が1本の線として双方向に接続します。直線から波線へ移る場合は、直線側の右70%と波線側の左70%を専用字形へ置換し、2文字の境界を中心とした全幅の70%（1.4文字幅）で各波形へ滑らかに移ります。振幅は遷移範囲の両端20%だけで変化速度を滑らかに増減し、中央60%では一定速度で変化させるため、境界付近だけ波形が急に立ち上がりません。直線側の左30%は端の筆形状を含む直線、波線側の右30%は本来の波形を保ちます。波線から直線へ移る場合は波線側の1文字を各波形から直線へ戻る字形へ置換します。両側を直線に挟まれた1文字だけの波線には、両端を直線へ一致させながら字面内に山と谷を残す専用字形を使用します。境界上の位置・接線・線幅を一致させ、接続面の輪郭を8 unitsずつ重ねるため、`うわ――〰〰`、`ーー〜〜ーー`、`〰〰――`、`ー〰ー`のような列でも境界に隙間や段差を作りません。`ss04`の1.25周期と`ss05`の1周期では、直線と波線の間の自動遷移を行いません。

連続する`ー`は、元字形の30%位置と70%位置で中心線を測り、中央を固定したアフィンシアーで右上がりの傾斜だけを打ち消してから、本文字形から求めた基準線幅へ揃えて始端・中間・終端へ分割します。端の筆形状は残しつつ、中央の直線と両端が同じ軸に見えるようにしています。単独の`ー`は元字形のままです。

`〰`はAdobe-Manga1のGSUB構造に合わせ、中央線から始まって中央線へ戻る1文字4半波の反復可能な中間字形を使用します。振幅、基準線、本文字形に揃えた線幅、山頂の曲率は`〜`と揃えています。単独字形の両端と連続時の外側の始端・終端には約50 unitsの余白、1/6文字幅のテーパーと0.3半波分の追加位相を持たせています。

## Manga1方式の濁点・半濁点付き仮名

Adobe-Manga1-0が規定する濁点77列と半濁点114列の計191列を、OpenTypeの`ccmp`で1グリフへ置換します。正式な入力には結合濁点（U+3099）または結合半濁点（U+309A）を使用します。入力互換のため、全角幅濁点（U+309B）または全角幅半濁点（U+309C）を基字に続けた場合も、既定で有効な`liga`により同じ一体字形へ置換します。`liga`を無効にすると全角幅記号だけが基字と分離し、単独のU+309B・U+309Cは設定にかかわらず変更しません。

```text
あ゙ ぁ゙ な゙ ん゙ ア゙ ン゙
か゚ あ゚ さ゚ な゚ ま゚ セ゚ ツ゚ ㇷ゚
ー゙
```

Noto版では、Noto Serif JPに一体字形がある24列は既存輪郭を使用し、残る167列は基字と結合記号の輪郭を一体化します。Regularで字ごとに決めた配置を基準に、ほかの6ウェイトも全191列の横組・縦組を目視し、ウェイト専用JSONへ個別調整を記録しています。生成時の自動移動は行いません。源暎こぶり明朝版では、同フォントに既存する88列の一体字形を優先し、残る103列には同フォントの既存字形から測定して目視調整した専用配置を使用します。小書き仮名では記号を縮小して基字へ近づけ、横組・縦組それぞれに専用字形を生成します。

源暎こぶり明朝が一体字形を持つ濁点74列・半濁点14列の計88列には、同フォントと互換性のある私用領域U+E082–U+E0D9も割り当てています。たとえばU+E082を直接入力しても、`あ` + U+3099と同じ字形になります。OpenTypeの結合処理に対応しないアプリで使用できます。

長音`ー`（U+30FC）に結合濁点を続けた字形も、横組・縦組それぞれの一体字形へ置換します。源暎こぶり明朝版は元フォントの既存字形を保持し、Noto版はその相対配置を1000 units/emへ正規化して各ウェイトの`ー`と濁点から生成します。完成字形は両ファミリーとも私用領域U+E0DBで直接入力できます。

白ハート`♡`（U+2661）と黒ハート`♥`（U+2665）に結合濁点を続けた2列も一体字形へ置換します。私用領域の基字U+E064・U+E065でも同じ結合が働き、完成字形はそれぞれU+E0DC・U+E0DDで直接入力できます。源暎こぶり明朝版は、通常のハート、私用領域の基字、完成字形、4つの`ccmp`入力を含めて元フォントの既存字形と対応を変更せず保持します。Noto版だけは各ウェイトのハートと濁点から字形を生成し、配置後の濁点2画の中心間距離の1/3を白抜き半径として、濁点を16方向へ拡張した範囲をハートから差し引きます。

全角感嘆符`！`（U+FF01）と全角疑問符`？`（U+FF1F）にも、結合濁点または結合半濁点を続けた4列を用意しています。`ccmp`で全角1文字幅の一体字形へ置換し、横組・縦組それぞれの専用字形を使用します。Noto版7ウェイトと源暎こぶり明朝版Regularについて、4列すべての配置を個別に記録しています。

```text
！゙ ！゚ ？゙ ？゚
```

実験的なCFF2可変版にも、この4列とハート2列を収録しています。200、300、400、500、600、700、900の7マスターから各ウェイトの輪郭と配置を補間し、全角感嘆符・疑問符には横組・縦組の専用字形を用意します。ハート2列は濁点周囲の白抜きを保ったまま、ウェイト間で補間できる共通の三次ベジェ構造へ正規化しています。

元フォントにない場合、`𛄲`（U+1B132、Hiragana Letter Small Ko）と`𛅕`（U+1B155、Katakana Letter Small Ko）は、ベースフォントの`こ`と`コ`を既存の小書き仮名に合わせて縮小・配置した横組・縦組字形として追加します。

源暎こぶり明朝版では、通常のかな、数字、約物と、Manga1が規定する半濁点付き14列（`ㇷ゚`、`か゚`、`き゚`、`く゚`、`け゚`、`こ゚`、`カ゚`、`キ゚`、`ク゚`、`ケ゚`、`コ゚`、`セ゚`、`ツ゚`、`ト゚`）を、OpenTypeの`ruby`で元フォントのルビ専用字形へ置換します。小書き仮名、小書きコ、`ㇷ゚`などには縦組専用ルビ字形もあります。Nobigoe MinchoとNobigoe Novel Minchoにはこれらのルビ字形を移植せず、ベースのNoto Serif JPが持つ既存の`ruby`機能を変更せず保持します。

## Manga1方式の感嘆符・疑問符合字

全角の`！`（U+FF01）と`？`（U+FF1F）による次の16通りを、OpenTypeの`ccmp`で全角1文字幅の合字へ置換します。

```text
？？   ？？？
！！   ！！！   ！！！！   ！！！！！
？！   ！？
？？！ ？！？   ！？？
！！？ ！？！   ？！！
！！？？ ？？！！
```

単独の`！`と`！！`、`！！！`、`！！！！`には、しっぽり明朝に収録された直立字形U+E000、U+E002、U+E007、U+E0E3を使用します。`！！！！！`はU+E002から直立感嘆符の構成輪郭を抽出し、1文字セルへ再配置して生成します。2記号の`？？`、`？！`、`！？`は、それぞれ既存合字`⁇`（U+2047）、`⁈`（U+2048）、`⁉`（U+2049）の輪郭を使用します。その他の3記号以上では、直立感嘆符と既存合字から抽出した疑問符を再配置します。横組・縦組とも記号はセル内で横並びになります。半角ASCIIの`!`と`?`は合字化しません。

単独の全角`！`・`？`と16通りの合字には、明朝と時計回り10度の回転字形を用意しています。回転字形は感嘆符・疑問符それぞれの本体と下点を剛体回転し、輪郭そのものは変形しません。回転後に本体上端を元の上端、下点下端を元の下端へ垂直移動し、本体輪郭間の左右間隔を回転前の字形から復元して合字全体を中央へ再配置します。4〜5連で復元した間隔のまま全角セルへ収まらない場合は、本体全体を960 units以内に保ちながら各間隔を最低20 units確保します。太ウェイトで10度の回転ではこの最低間隔を確保できない場合に限り、輪郭を変形せず回転角を小さくします。これにより、合字を構成する記号の上端と下端は共通する水平な平行ガイドへ揃います。既定は明朝です。`ss01`で回転字形へ切り替えられ、回転字形は`aalt`にも登録されています。単独の明朝`！`と2〜4連の明朝感嘆符合字、および単独の明朝`？`はしっぽり明朝の字形を使用し、その他の明朝合字もしっぽり明朝をもとに全角1文字幅へ収めています。Noto版の明朝合字はMedium、SemiBold、Bold、Blackでそれぞれしっぽり明朝Medium、SemiBold、Bold、ExtraBoldを使用します。しっぽり明朝に400未満がないため、ExtraLight、Light、RegularはRegularを使用します。そのままでは和文との太さが揃わないため、しっぽり明朝の単独字形と全合字には、Noto Serif JPの全角`！`・`？`を基準にした-13〜+11 unitsのウェイト別輪郭補正を適用します。

実験的なCFF2可変版の既定明朝は、ExtraLightだけを細ウェイト用に再設計し、Light以上はしっぽり明朝のウェイト別骨格を直接使用します。ExtraLightの`？`本体は18本、`！`本体は6本の三次ベジェで構成し、`？`右下の内側は節点間で接線と曲率が連続するC2スプラインです。Light・Regularにはしっぽり明朝Regular、Medium・SemiBold・Bold・BlackにはそれぞれMedium・SemiBold・Bold・ExtraBoldの輪郭を使用します。しっぽり明朝の`？`本体を構成する14本の三次ベジェは、右下内側の1曲線だけをde Casteljau分割して18本へ変換します。この分割は元曲線の形を変えず、全7ウェイトを補間互換にします。黒みの基準にはNoto Serif JPの約物ではなく、各ウェイトの`川`・`目`・`田`から測った漢字縦主線の中央値を使用します。疑問符は外側の骨格を保ったまま右側太線の内周を細め、感嘆符は上部テーパーを左右から細めることで、ExtraLightで確認した漢字主線との光学差を全ウェイトへ維持します。下点は元輪郭の上端を維持しながら、ExtraLight、Regular、Blackで元直径の84%、87%、90%へ光学補正した正円です。`！！！！！`は各`！`の中心を全角セル内の100、300、500、700、900 unitsへ配置し、隣の全角セルへ続けても内部とセル境界の間隔が等しくなります。回転字形にも固定版と同じ剛体回転、上下端整列、左右間隔再配置を適用し、各マスターの輪郭変形を避けたまま補間互換性を維持します。
疑問符の下点は本体全体の外接中心ではなく、下へ伸びる線の終端中心へ揃えます。

この機能は[Adobe-Manga1-0](https://github.com/adobe-type-tools/Adobe-Manga1)の合字シーケンス集合、異体字構成、GSUB規則を参考にしています。Adobe-Manga1のCIDコレクション全体を実装するものではありません。

## OpenType機能一覧

| feature | 用途 |
|---|---|
| `ccmp` | 全角感嘆符・疑問符合字、濁点・半濁点付き仮名の合成 |
| `liga` | 全角幅濁点・半濁点を既存の一体字形へ置換 |
| `aalt` | 全角感嘆符・疑問符および合字の回転字形を列挙 |
| `ss01` | 全角感嘆符・疑問符および合字を回転字形へ置換 |
| `ss04` | 連続する`〜`・`～`を1文字1.25周期の波形へ置換 |
| `ss05` | 連続する`〜`・`～`を1文字1周期の波形へ置換 |
| `ruby` | 対応するかな、数字、約物、Manga1の半濁点付きルビ14字形へ置換（のびごえこぶり明朝のみ） |
| `calt` | 連続する長音・ダッシュ・波線の始端／中間／終端置換と、`〰`・`〜`・`～`間の双方向周波数遷移 |
| `vert` / `vrt2` | 縦組用の伸長記号、濁点・半濁点付き仮名、および`ㇷ゚`のルビ字形（ルビ字形はのびごえこぶり明朝のみ） |

一般的なシェーピングエンジンでは`ccmp`、`liga`、`calt`は既定で有効です。アプリケーション側で`liga`を無効にするとU+309B・U+309Cは全角幅の独立字形になり、結合文字U+3099・U+309Aの`ccmp`は維持されます。ただし、欧文の`fi`・`fl`などの標準合字も同時に無効になります。`calt`を無効にすると、同種の伸長記号の自動連結と`〰`・`〜`・`～`間の周波数遷移は行われません。

CSSでは、たとえば`font-feature-settings: "liga" 0;`で全角幅濁点・半濁点を分離し、`font-feature-settings: "ss01" 1;`で全角感嘆符・疑問符を回転字形へ変更できます。波線は`font-feature-settings: "ss04" 1;`で1文字1.25周期、`font-feature-settings: "ss05" 1;`で1文字1周期へ切り替えます。`ss04`と`ss05`はどちらか一方だけを指定し、両方とも無効なら既定の1文字1.5周期です。のびごえこぶり明朝では、`font-feature-settings: "ruby" 1;`で対応字形をルビ専用字形へ切り替えられます。
